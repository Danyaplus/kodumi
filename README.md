# Kodumi — корпоративный сайт

Статический сайт HTML/CSS/JavaScript. Python 3.12+ (рекомендуется 3.13) нужен только для сборки. На хостинге Python, Node.js, PHP и база данных не нужны.

## Архитектура

- `index.html` — готовая главная в корне репозитория для предпросмотра, автоматически обновляется сборкой. Ссылки ведут в `dist/`.
- `frontend/assets/` — исходные CSS, JS, логотип, графика.
- `frontend/data/site.json` — настройки и каталог проектов/технологий.
- `frontend/src/config.py` — загрузка настроек и валидация.
- `frontend/src/components.py` — шапка, подвал, карточки и общие компоненты.
- `frontend/src/pages.py` — содержимое страниц и маршруты.
- `frontend/src/render.py` — шаблон HTML и SEO-метаданные.
- `frontend/build.py` — сборка.
- `backend/` — резерв для будущего серверного API, сейчас не используется.
- `dist/` — полностью готовый сайт, включая свой корневой `index.html`, страницы, `robots.txt`, `sitemap.xml`, `404.html`. Генерируется автоматически; не редактируйте вручную. В архиве уже присутствует для удобства.
- `.github/workflows/pages.yml` — автопубликация GitHub Pages.

## Локальный запуск

Из корня проекта:

```sh
python -m http.server 8000 --directory dist
```

Откройте http://localhost:8000/. Для пересборки после изменений: `python frontend/build.py`. На Windows можно использовать `py` вместо `python`. Если открываете сервер в корне репозитория, главная также доступна как предпросмотр; полноценное тестирование проводите с `--directory dist`.

## GitHub Pages

1. Создайте публичный репозиторий `kodumi`, загрузите всё содержимое архива, включая скрытые `.github` и `.gitignore` (надёжнее через Git).
2. Settings → Pages → Build and deployment → Source → **GitHub Actions**.
3. В Actions выберите `Deploy Kodumi to GitHub Pages` и Run workflow на main, если первый push ещё не запустил публикацию. Последующие push в main запускают сборку и публикацию автоматически.
4. Workflow получает реальный базовый URL из GitHub Pages, генерирует canonical, Open Graph, sitemap и 404 для этого адреса, затем публикует только `dist/`. Исходники не попадают на сайт (но видны в публичном репозитории).

На обычном хостинге: укажите настоящий `siteUrl` в `frontend/data/site.json` и выполните сборку. Загрузите **содержимое** `dist/` в `public_html` (или корень сайта), включая `.htaccess` для Apache/LiteSpeed. Настройте HTTPS и выдачу index.html из папок. Для Nginx настройте `index index.html;` и `error_page 404 /404.html;`. `404.html` — страница для неверных URL, должна отдаваться с HTTP 404, а не 200. Не используйте SPA fallback. При смене домена пересоберите сайт.

## SEO

На каждой странице свой HTML и метаданные. `sitemap.xml` включает индексируемые маршруты. Для GitHub Pages проекта в подпапке robots.txt в этой подпапке не управляет обходом всего домена: поисковики читают robots.txt только из корня домена. Sitemap можно отдельно отправить в Search Console. При собственном домене robots.txt будет в правильном корне. Демонстрационный домен kodumi.example в локальной сборке необходимо заменить перед обычной публикацией; GitHub Actions заменяет его автоматически.

## Как добавлять проекты

В `frontend/data/site.json` массив `projects` содержит данные карточек и страниц. Добавьте объект по образцу Kodumi Games:

```json
{
  "slug": "my-python-app",
  "name": "My Python App",
  "category": "software",
  "status": "Опубликован",
  "featured": true,
  "summary": "Короткое описание.",
  "description": "Полное описание проекта.",
  "technologies": ["python", "sql"],
  "features": ["Возможность 1", "Возможность 2"],
  "url": "",
  "image": "assets/my-python-app.webp"
}
```

Положите обложку в `frontend/assets/`; в JSON путь по-прежнему `assets/...`. `slug` — уникальный латинский идентификатор с дефисами. Категории: `web`, `games`, `software`, `bots`, `other`. Технологии — идентификаторы из массива `technologies`. `featured: true` выводит проект на главной. `url` — внешний адрес продукта, если существует. После редактирования запустите генератор. Новый проект автоматически появится в общем каталоге, своей категории, связанных технологиях и sitemap; будет создана отдельная HTML-страница с метаданными. Для новых технологий также добавьте объект в `technologies` и пересоберите сайт.

## Страницы и навигация

- `/` — главная; `/projects/` — каталог; `/projects/kodumi-games/` — подробности проекта.
- `/projects/category/web/`, `/projects/category/software/` и другие категории.
- `/technologies/`, `/technologies/python/`, `/technologies/php/` и остальные технологии.
- `/services/`, `/about/`, `/contacts/`, `/portfolio/`, `/privacy/`, `/terms/`.
- `404.html` — страница ошибки. Настройте её на хостинге как документ для HTTP 404.

Каждая страница — полноценный HTML с собственным URL, заголовком, description, canonical, Open Graph, Twitter Card и JSON-LD. При включённом JavaScript переходы заменяют содержимое `<main>`, обновляют URL и метаданные, поддерживают историю браузера. Шапка и подвал не пересоздаются. Без JS обычные ссылки также работают. Шапка закреплена сверху; подвал находится внизу страницы, не перекрывая экран.


Укажите реальные контакты и ссылки в `frontend/data/site.json`. Политика конфиденциальности и условия использования пока шаблонные (noindex); уточните их перед публичным продвижением в `frontend/src/pages.py`. Не добавляйте пароли и API-ключи в публичный репозиторий.
